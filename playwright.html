Look at the assertion

This reconstruction shows two of the visibility checks with fictional labels. The original implementation uses BDD step definitions and page objects; this shortened test makes the intent readable.

Reconstructed example · fictional route and labels
import { test, expect } from '@playwright/test';

test('sign-in fields are visible', async ({ page }) => {
  // Assumes a configured demo baseURL and /sign-in route.
  await page.goto('/sign-in');
  const emailField = page.getByLabel('Email address', {
    exact: true
  });
  const passwordField = page.getByLabel('Password', {
    exact: true
  });

  await expect(emailField).toBeVisible();
  await expect(passwordField).toBeVisible();
});

AI-assisted reconstruction for this portfolio, not original client code or a new test run. It illustrates a subset of the reviewed case. Visibility assertions alone do not verify credentials, sign-in success, or error handling.
